# M4 source coverage decision

Status: **Approved September 16, 2026.** This decision replaces the original two-or-three-project-source target. One document supplies project evidence; the second remains context only.

## Evidence available

The current pilot has fifteen manually reviewed allocations in three Nyeri wards for FY 2026/2027. All project observations come from the approved programme budget. The retained itemized estimates are registered for context and do not supply project answers. The application discloses those roles.

Additional source checks have not established a second usable set of comparable, ward-specific project allocations:

| Official document | Assessment for this pilot |
| --- | --- |
| [Approved itemized estimates](https://www.nyeri.go.ke/wp-content/uploads/2026/07/Approved-UPLOADED-Budget-Estimates-2026-27.pdf) | The inspected entries group several works or lack a ward field. A project name alone cannot establish the ward or justify assigning a grouped amount to a single project. |
| [Approved Mwananchi budget](https://www.nyeri.go.ke/wp-content/uploads/2026/07/MWANANCHI_BUDGET_FY_2026-27.pdf) | The inspected hospital summary rounds a figure from the itemized estimates; it is not a second exact project observation. |
| [Assembly budget statement for FY 2026/27](https://nyeriassembly.go.ke/download/budget-statement-for-the-fiscal-year-2026-27/) | Expenditure priorities on printed pages 15–17 provide grouped infrastructure/sector allocations, not an exact allocation for a named project in one of the three pilot wards. Checked September 16, 2026; not imported. |
| [Approved annual development plan](https://www.nyeri.go.ke/wp-content/uploads/2026/02/Approved-ADP-2026-2027.pdf) | Project estimates in a development plan must not be relabeled as approved budget allocations. This would require a different evidence category and appropriate user wording. It has not been imported. |

These findings concern the inspected documents and entries. They do not prove that no other suitable official document exists.

## Approved adjustment

Finish the hackathon pilot with the fifteen reviewed records already tested, using one project-answer document and retaining the second official PDF as registered context. Keep the source-count and allocation limitations visible. Do not introduce a new year, wards, or financial observation type to satisfy a document count.

The M4 dataset condition is now:

> Maintain 15–30 reviewed project records from at least one official project-level document. Register any additional official documents separately, and state whether they supply project answers or context only. Do not claim independent corroboration from a registered document without comparable reviewed evidence.

The implementation plan, product requirements, source guidance, README, and handoff checklist reflect this decision. The original two-or-three-document target was an internal implementation target, not a requirement listed in the hackathon announcement. See [submission requirements](demo-runbook.md#submission-requirements).
